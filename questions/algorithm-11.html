QUESTION 101#center_style_original_202608_0064

得点表を得点の高い順に並べ、得点が同じ行は氏名の文字コード順に並べたい。指定する並べ替え条件を次から選べ。

  1. 0

    第1キーを得点の昇順、第2キーを氏名の降順にする

  2. 1

    第1キーを得点の降順、第2キーを氏名の昇順にする

  3. 2

    第1キーを氏名の昇順、第2キーを得点の降順にする

  4. 3

    第1キーを得点の降順、第2キーを氏名の降順にする

正答と解説を確認

正答1. 第1キーを得点の降順、第2キーを氏名の昇順にする

解説

複数キーの並べ替えでは、第1キーで全体を大きく分け、第1キーが同じ行だけを第2キーで並べる。したがって、まず優先順位を決め、各キーについて昇順か降順かを別々に確認するとよい。

QUESTION 102#center_style_original_202608_0065

変数xを0で初期化し、「x＜10である間、xに3を加える」という前判定の繰返しを実行した。終了時のxを次から選べ。

  1. 0

    12

  2. 1

    13

  3. 2

    10

  4. 3

    9

正答と解説を確認

正答0. 12

解説

前判定の繰返しでは、処理の前に条件を確かめる。xは0、3、6、9、12と変化し、12になった後の判定で終了する。終了時の値は境界値10と一致するとは限らず、増加量3だけ通り越すことがある。

QUESTION 103#center_style_original_202608_0081

動画視聴が深夜まで続き、睡眠不足と遅刻が繰り返されている。生活への影響を減らす対応として最も適当なものを次から選べ。

  1. 0

    平日の終了時刻を決めず、睡眠不足は休日の長時間睡眠だけで補えばよいとする

  2. 1

    利用時間の目標は立てるが、通知を有効にした端末を枕元へ置き、記録は確認しない

  3. 2

    利用記録を振り返って終了時刻や利用時間の制限を設け、通知を止め、改善しなければ周囲へ相談する

  4. 3

    視聴履歴を削除し、実際の終了時刻や総利用時間は変えない

正答と解説を確認

正答2. 利用記録を振り返って終了時刻や利用時間の制限を設け、通知を止め、改善しなければ周囲へ相談する

解説

実態把握、具体的制限、刺激の削減、支援の利用を段階的に組み合わせている。休日の寝だめだけでは平日の視聴行動と遅刻の原因を減らせず、睡眠リズムも整えにくい。

QUESTION 104#center_style_original_202608_0094

複数の組織が保有する計算資源をネットワーク経由で連携させ、一つの大規模計算を分担させる方式を次から選べ。

  1. 0

    一台の高性能計算機だけで処理し、他組織の計算資源とは連携しないスタンドアロン方式

  2. 1

    利用場所の端末だけで即時処理し、広域の計算資源を一つの課題へ分担させないエッジ処理

  3. 2

    一事業者の仮想化資源を必要時に借りることだけを指し、組織横断の分散計算を要件としないクラウドサービス

  4. 3

    複数組織の分散した計算資源を連携させるグリッドコンピューティング

正答と解説を確認

正答3. 複数組織の分散した計算資源を連携させるグリッドコンピューティング

解説

地理的・組織的に分散した計算資源をネットワークで結び、大規模計算を分担する方式と捉えられる。計算主体が一台に閉じており、複数組織の資源を連携させる条件を満たさない。

QUESTION 105#center_style_original_202608_0127

地域の環境調査で集めた多数の観測項目から、目的に必要な特徴だけを選び、不要な細部を省いて簡潔なモデルにする操作を次から選べ。

  1. 0

    必要な特徴を選び、不要な細部を省く抽象化

  2. 1

    収集した全項目を細部までそのまま再現する具体化

  3. 2

    項目間の親子関係だけを付け、情報量を減らさない構造化

  4. 3

    観測値の単位をそろえて尺度を変える標準化

正答と解説を確認

正答0. 必要な特徴を選び、不要な細部を省く抽象化

解説

目的に関係する特徴を残し、それ以外を捨象して簡潔なモデルにする操作と捉えられる。具体化は細部を付加して個別的な表現へ近づける方向で、不要な細部を省く操作と逆である。

QUESTION 106#center_style_original_202608_0144

正方形の中へ乱数で点を多数発生させ、内接する4分の1円の中に入った点の割合から円周率を近似する。この方法の説明として最も適当なものを次から選べ。

  1. 0

    点を発生させず、正方形と円の面積公式だけを記号計算して厳密値を求める方法である

  2. 1

    点の個数を一つずつ増やし、起こり得る座標の組を有限個として漏れなく列挙する方法である

  3. 2

    発生した点のx座標だけを説明変数とする回帰直線を求め、傾きから円周率を決める方法である

  4. 3

    乱数による試行を繰り返し、円内に入る割合という標本結果から求めたい値を近似する方法である

正答と解説を確認

正答3. 乱数による試行を繰り返し、円内に入る割合という標本結果から求めたい値を近似する方法である

解説

正方形内で一様に点を選ぶと、4分の1円に入る割合はおよそπ/4になるため、「4×円内の点数÷全点数」でπを近似できる。試行回数を増やすと一般にばらつきは小さくなるが、有限回で厳密値になるとは限らない。

QUESTION 107#center_style_original_202608_0145

あるシミュレーション結果は平均値102、四分位範囲18であり、比較対象の実データは平均値108、四分位範囲26であった。調整後の候補について、平均値の差の絶対値と四分位範囲の差の絶対値の合計が最も小さいものを次から選べ。

  1. 0

    平均値102、四分位範囲25

  2. 1

    平均値107、四分位範囲25

  3. 2

    平均値107、四分位範囲18

  4. 3

    平均値110、四分位範囲24

正答と解説を確認

正答1. 平均値107、四分位範囲25

解説

平均値は分布の中心、四分位範囲は中央50％のデータの広がりを表す。選択肢1では実データとの差が平均値で1、四分位範囲で1なので、指定された合計は1＋1＝2となる。他の候補の合計は順に7、9、4であるため、中心と散らばりを合わせて最も近づけているのは選択肢1である。

QUESTION 108#center_style_original_202608_0184

駅名と、その駅の1日当たりの乗車人数をプログラムの変数に格納する。データ型の組合せとして最も適当なものを次から選べ。

  1. 0

    駅名は論理型、乗車人数は文字列型

  2. 1

    駅名は文字列型、乗車人数は整数型

  3. 2

    駅名は整数型、乗車人数は論理型

  4. 3

    駅名は実数型、乗車人数は画像データ型

正答と解説を確認

正答1. 駅名は文字列型、乗車人数は整数型

解説

駅名は文字の並びなので文字列型、人数は人数を示す小数部のない数なので整数型が適している。論理型は真・偽の二値を扱うため駅名を表せず、文字列型の人数はそのままでは加算や大小比較に適さない。

QUESTION 109#center_style_original_202608_0185

プログラムで変数totalを0に初期化し、数値を1個入力するたびに「total = total + 入力値」を実行する。変数totalの役割を次から選べ。

  1. 0

    直前に入力した値だけを保持する

  2. 1

    入力回数を1ずつ数える

  3. 2

    これまでに入力した値の合計を累積して保持する

  4. 3

    入力値のうち最大の値を保持する

正答と解説を確認

正答2. これまでに入力した値の合計を累積して保持する

解説

初期値0に各入力値を順次加えるため、totalには処理済みの全入力値の合計が保持される。直前の値を代入するだけならtotal=入力値とする。この命令は以前のtotalへ新しい入力値を加える。

QUESTION 110#center_style_original_202608_0231

マス番号1をSTART、マス番号26以上をGOALとするすごろくで、1回ごとに必ず1～6マス進む。全ての出目の並びについて、遅くともGOALへ到達すると保証できる最小の回数を次から選べ。

  1. 0

    5回

  2. 1

    24回

  3. 2

    25回

  4. 3

    26回

正答と解説を確認

正答2. 25回

解説

『必ず到達する最小回数』は、最も進まない出目が続く場合で上限を調べる。開始位置1からゴール26までは25マスあり、最小でも毎回1マス進むので25回で到達する。平均的な出目ではなく、条件内で最も不利な場合を使う。

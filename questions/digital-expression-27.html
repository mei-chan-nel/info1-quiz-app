QUESTION 261#center_style_original_202608_0089

医療画像の診断記録には原画像の画素値を完全に保持する要件があり、Webページの背景写真では多少の画質低下を許容して容量を小さくしたい。圧縮方針を次から選べ。

  1. 0

    両方とも復元可能性を確認せず、最小容量になる非可逆圧縮だけを選ぶ

  2. 1

    診断記録には可逆圧縮、背景写真には許容画質を確認した非可逆圧縮を用いる

  3. 2

    診断記録には非可逆圧縮を用い、失った画素値を展開時に完全復元する

  4. 3

    背景写真を可逆圧縮すれば、同程度の見た目を保つ非可逆圧縮より容量を小さくできる

正答と解説を確認

正答1. 診断記録には可逆圧縮、背景写真には許容画質を確認した非可逆圧縮を用いる

解説

圧縮方式は用途の要件から選ぶ。1ビットも変えずに戻す必要があれば可逆圧縮、多少の違いを許して容量を抑えたい場合は非可逆圧縮が候補になる。『可逆なら常に小さい』『非可逆でも後で完全復元できる』とは限らない。

QUESTION 262#center_style_original_202608_0090

文字をバイト列で表す方式の一つであるUTF-8について、英字と日本語を含む文書を交換する場合の説明を次から選べ。

  1. 0

    Unicodeで各文字に割り当てた番号を、値に応じて1～4バイトで表す可変長方式である

  2. 1

    英字と日本語を同じ2バイトで表す固定長方式である

  3. 2

    Unicodeの文字を4バイト固定で表し、短いバイト列は用いない方式である

  4. 3

    ASCIIと同じ英字にも別の値を割り当てるため、ASCIIのバイト列とは互換性がない方式である

正答と解説を確認

正答0. Unicodeで各文字に割り当てた番号を、値に応じて1～4バイトで表す可変長方式である

解説

ASCIIと共通する英数字は1バイト、日本語の多くは3バイトで表される。同じ文字数でも文字の種類によってデータ量が異なるため、「文字数×固定バイト数」とは限らない。

QUESTION 263#center_style_original_202608_0091

アナログ音声をPCM方式でデジタルデータにする基本的な処理順を次から選べ。

  1. 0

    量子化→暗号化→標本化

  2. 1

    符号化→復号→標本化

  3. 2

    標本化→量子化→符号化

  4. 3

    圧縮→標本化→復号

正答と解説を確認

正答2. 標本化→量子化→符号化

解説

時間方向に値を取り出す標本化、値を有限段階へ丸める量子化、段階番号をビット列にする符号化の順で処理する。連続信号から測定時点を取り出す前に測定値を量子化することはできず、暗号化はPCM変換の基本段階でもないといえる。

QUESTION 264#center_style_original_202608_0092

センサが250マイクロ秒ごとに1回測定する。1秒を1000000マイクロ秒とするとき、1秒間の測定回数を次から選べ。

  1. 0

    1000回

  2. 1

    4000回

  3. 2

    250回

  4. 3

    250000回

正答と解説を確認

正答1. 4000回

解説

一定間隔で測定するとき、1秒間の回数は「1秒の長さ÷測定間隔」で求める。1秒＝1,000,000マイクロ秒なので、1,000,000÷250＝4,000回である。時間の単位をそろえてから割ることが重要である。

QUESTION 265#center_style_original_202608_0101

写真のバックアップ先として外付けSSD、USBメモリ、クラウドストレージを比較する際の説明を次から選べ。

  1. 0

    外付けSSDとクラウドストレージを併用し、少なくとも一つは自宅と別の場所で管理する

  2. 1

    内蔵SSDの別フォルダへ三つコピーし、同じコンピュータだけで保管する

  3. 2

    USBメモリ一つへ毎月コピーするが、コピー後にファイルを開けるかは確認しない

  4. 3

    クラウドストレージ一つだけへ保存し、アカウントの多要素認証は設定しない

正答と解説を確認

正答0. 外付けSSDとクラウドストレージを併用し、少なくとも一つは自宅と別の場所で管理する

解説

バックアップはコピー数だけでなく、同じ原因で同時に失われないかを考える。代表的な3-2-1の考え方は、データを3個持ち、2種類の媒体を使い、1個を別の場所に置くというものだ。さらに、実際に復元できるかを定期的に確かめる。

QUESTION 266#center_style_original_202608_0102

プログラムのソースコードと、多少の画質低下を許容して容量を減らすWeb公開用写真に適した圧縮方針の組合せを次から選べ。

  1. 0

    両方を非可逆圧縮し、失った文字や画素は利用時に推測する

  2. 1

    両方を暗号化すれば、圧縮方式や復元可能性を考えなくてよい

  3. 2

    ソースコードには非可逆圧縮を使い、写真は画質を保つため無圧縮に限る

  4. 3

    ソースコードは可逆圧縮し、写真は許容画質を確認して非可逆圧縮も利用する

正答と解説を確認

正答3. ソースコードは可逆圧縮し、写真は許容画質を確認して非可逆圧縮も利用する

解説

コードは完全復元が必要なので可逆圧縮、写真は見た目への影響を確認しながら非可逆圧縮を選べる。ソースコードの1文字でも失えば動作や意味が変わり得るため、推測に頼る非可逆圧縮は適さない。

QUESTION 267#center_style_original_202608_0103

非可逆圧縮した画像を展開し、その展開結果を同じ非可逆圧縮方式・設定で何度も保存し直した場合の説明を次から選べ。

  1. 0

    保存回数が増えるほど、最初に失われた細部が正確に復元される

  2. 1

    非可逆圧縮した画像も、展開すれば撮影時の元データへ戻る

  3. 2

    保存のたびに追加の情報が失われ、画質劣化が累積することがある

  4. 3

    非可逆圧縮は情報を追加して画質を保つため、元データより容量が大きくなる

正答と解説を確認

正答2. 保存のたびに追加の情報が失われ、画質劣化が累積することがある

解説

展開した近似値を再び丸めたり変換したりするため、新たな誤差が加わって劣化が累積する場合がある。一度捨てた細部は後の再圧縮で利用できず、保存回数を増やしても元の情報は復元されないといえる。

QUESTION 268#center_style_original_202608_0112

16ビットのアドレスで0番地から1バイト単位に番地を付ける主記憶装置がある。指定できる最大容量を次から選べ。

  1. 0

    64 KiB

  2. 1

    16 KiB

  3. 2

    64 MiB

  4. 3

    4 GiB

正答と解説を確認

正答0. 64 KiB

解説

nビットのアドレスでは2ⁿ個の番地を区別できる。各番地が1バイトなら容量は2ⁿバイトとなり、16ビットでは2¹⁶バイト＝64 KiBである。

QUESTION 269#center_style_original_202608_0113

0番地から1バイト単位に番地を付ける主記憶装置で、最大4 GiBをすべて番地指定するために最低限必要なアドレス長を次から選べ。

  1. 0

    16ビット

  2. 1

    64ビット

  3. 2

    24ビット

  4. 3

    32ビット

正答と解説を確認

正答3. 32ビット

解説

1バイト単位で番地を付けるなら、nビットのアドレスで指定できる容量は2ⁿバイトである。4 GiB＝4×2³⁰＝2³²バイトなので、最低32ビットが必要になる。

QUESTION 270#center_style_original_202608_0116

CPU内部で、演算の入力値や結果などを一時保持し、主記憶装置より一般に小容量で高速にアクセスできる記憶場所を次から選べ。

  1. 0

    主記憶より小容量で高速だが、CPU外部で命令やデータのコピーを保持するキャッシュメモリ

  2. 1

    実行中のプログラムをCPU外部で保持する主記憶装置

  3. 2

    演算の入力値や結果をCPU内部で直接保持するレジスタ

  4. 3

    電源断後もファイルを長期保存する補助記憶装置

正答と解説を確認

正答2. 演算の入力値や結果をCPU内部で直接保持するレジスタ

解説

レジスタは、演算の入力値や結果などをCPU内部で一時的に保持する、小容量で高速な記憶場所である。主記憶装置は実行中の命令やデータを広く保持し、補助記憶装置はファイルを長期間保存する。

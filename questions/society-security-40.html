QUESTION 391#center_style_original_202608_0123

日本で、小説や絵画など著作権法上の著作物を創作した時点に、権利取得の申請や登録をしなくても原則として発生する権利を次から選べ。

  1. 0

    意匠権

  2. 1

    実用新案権

  3. 2

    特許権

  4. 3

    著作権

正答と解説を確認

正答3. 著作権

解説

著作権は著作物を創作した時点で自動的に発生し、権利取得のための申請・登録を要しない無方式主義を採る。意匠権は物品・建築物・画像のデザイン等について出願し、設定登録を受けて発生する産業財産権と捉えられる。

QUESTION 392#center_style_original_202608_0125

道路のセンサ、信号制御、車への交通情報配信などを情報通信で連携させる高度道路交通システム（ITS）の活用例として、最も適当なものを次から選べ。

  1. 0

    道路の混雑情報を集め、信号制御や経路案内へ反映する

  2. 1

    店舗の会計時に商品コードを読み取り、売上と在庫を更新する

  3. 2

    建物の設計図をコンピュータ上で作成し、寸法を修正する

  4. 3

    企業全体の会計・人事・生産データを統合して業務を管理する

正答と解説を確認

正答0. 道路の混雑情報を集め、信号制御や経路案内へ反映する

解説

ITSでは、道路・車両・利用者から得た情報を通信で結び、渋滞情報の提供、信号制御、安全運転支援などへ利用する。名称を覚えるだけでなく、「交通に関する情報を集め、共有し、制御や案内へ返す」という流れを押さえるとよい。

QUESTION 393#center_style_original_202608_0137

攻撃者が職員を装って電話し、「至急必要」として利用者のパスワードを聞き出そうとした。手口と適切な対策の組合せを次から選べ。

  1. 0

    フィッシングであり、メールのリンクではなく正規サイトから通知を確認する

  2. 1

    ブルートフォース攻撃であり、試行回数制限と長いパスワードを用いる

  3. 2

    ソーシャルエンジニアリングであり、本人確認済みの別経路で要求を確認して秘密を伝えない

  4. 3

    テールゲーティングであり、入室者一人ごとの認証を確認する

正答と解説を確認

正答2. ソーシャルエンジニアリングであり、本人確認済みの別経路で要求を確認して秘密を伝えない

解説

心理や権威を利用して秘密を引き出す手口であり、既知の連絡先など独立した経路で確かめる対策が合う。フィッシングは偽メールや偽サイトへの誘導が典型で、電話で権威と緊急性を使う今回の手口を最も直接には表さない。

QUESTION 394#center_style_original_202608_0138

障害や攻撃が起きても、必要なときに正当な利用者が情報やシステムへアクセスできる状態を保つ性質を次から選べ。

  1. 0

    責任追跡性

  2. 1

    完全性

  3. 2

    機密性

  4. 3

    可用性

正答と解説を確認

正答3. 可用性

解説

可用性は正当な利用者が必要なときに情報資産やサービスを利用できる性質である。責任追跡性は操作主体と行為を後から追える性質で、必要時にサービスが使えること自体の名称とはいえない。

QUESTION 395#center_style_original_202608_0141

公開鍵暗号方式の鍵管理と相手確認についての説明を次から選べ。

  1. 0

    公開鍵から秘密鍵を実用的な時間で簡単に求められることを安全性の前提とする

  2. 1

    公開鍵は配布できるが秘密鍵は所有者だけが安全に管理し、公開鍵と本人の対応も確認する

  3. 2

    秘密鍵も公開鍵と同じ配布場所で一般公開する

  4. 3

    受け取った公開鍵が目的の相手のものかを確認する必要はない

正答と解説を確認

正答1. 公開鍵は配布できるが秘密鍵は所有者だけが安全に管理し、公開鍵と本人の対応も確認する

解説

公開してよい鍵と秘密に保つ鍵を分け、秘密鍵を保護しつつ公開鍵の正当な所有者を確かめる必要になる。公開情報から秘密鍵を容易に計算できれば第三者も復号や署名偽造を行えるため、安全性が失われる。

QUESTION 396#center_style_original_202608_0142

通信開始時の鍵共有・相手認証に公開鍵暗号を用い、その後の大量データ通信に共通鍵暗号を用いるハイブリッド方式が採用される理由を次から選べ。

  1. 0

    公開鍵暗号と共通鍵暗号は、鍵の扱いも処理速度も同じなので用途を分けない

  2. 1

    公開鍵暗号は秘密鍵を全通信相手へ公開するため処理が速くなる

  3. 2

    共通鍵暗号には暗号化機能がなく、公開鍵暗号だけがデータを暗号化できる

  4. 3

    公開鍵暗号は安全な鍵共有に利用しやすく、共通鍵暗号は大量データを比較的高速に処理できる

正答と解説を確認

正答3. 公開鍵暗号は安全な鍵共有に利用しやすく、共通鍵暗号は大量データを比較的高速に処理できる

解説

公開鍵方式でセッション鍵を安全に合意・配送し、以後は高速な共通鍵方式で本文を処理することで長所を組み合わせる。一般に両方式は鍵の配り方と計算量に違いがあり、その違いがハイブリッド化の理由である。

QUESTION 397#center_style_original_202608_0153

利用者に同じパスワードを続けて2回入力させ、二つが一致した場合にログインさせる方式の認証要素についての説明を次から選べ。

  1. 0

    入力回数が2回なので、要素の種類が同じでも二要素認証になる

  2. 1

    知識要素一種類を繰り返すだけなので二要素認証ではない

  3. 2

    1回目を知識要素、同じ文字列の2回目を所有物要素として扱う

  4. 3

    一致確認を行えば、パスワード入力は生体要素へ変わる

正答と解説を確認

正答1. 知識要素一種類を繰り返すだけなので二要素認証ではない

解説

二つとも利用者が知っている同じ秘密であり、別の認証要素を組み合わせていない。要素数は入力回数ではなく、知識・所有物・生体など独立した種類で数える。

QUESTION 398#center_style_original_202608_0154

家庭の見守りカメラをインターネットへ接続して利用する際の安全対策を次から選べ。

  1. 0

    工場出荷時の共通パスワードを維持し、動作が変わる可能性を避けるため更新を止める

  2. 1

    家庭内で使う機器なので認証を省き、外部から接続できる管理画面だけを公開する

  3. 2

    家族が見やすいよう撮影データを認証不要のURLへ置き、URLを知る人に閲覧を許す

  4. 3

    初期パスワードを固有の強いものへ変更し、更新を適用し、外部公開と利用者権限を必要最小限にする

正答と解説を確認

正答3. 初期パスワードを固有の強いものへ変更し、更新を適用し、外部公開と利用者権限を必要最小限にする

解説

既知の初期認証情報を排除し、脆弱性修正と最小権限・最小公開を組み合わせることで侵入と映像漏えいの機会を減らす。共通初期パスワードは攻撃者に知られている可能性があり、更新停止は公表済み脆弱性を残す。

QUESTION 399#center_style_original_202608_0155

生成AIにおけるハルシネーションの説明を次から選べ。

  1. 0

    根拠がない、または事実と異なる内容や出典を、もっともらしく生成する現象

  2. 1

    学習データや設計の偏りにより、特定の集団へ不公平な出力傾向が生じることだけを指す

  3. 2

    外部の最新情報へ接続していないため、知識の更新時点が古いことだけを指す

  4. 3

    入力中の悪意ある指示によって、システムの本来の指示を無視させようとする攻撃

正答0. 根拠がない、または事実と異なる内容や出典を、もっともらしく生成する現象

解説

ハルシネーションは、生成AIが根拠のない事実や出典をもっともらしく示す現象である。学習データの偏りによる不公平、知識の古さ、悪意ある指示によるプロンプトインジェクションとは分けて考える。

QUESTION 400#center_style_original_202608_0158

パスワードと、登録した電話番号へSMSで届く一時コードを組み合わせる認証について、安全上の限界を正しく説明したものを次から選べ。

  1. 0

    パスワードとSMSコードはいずれも知識要素であり、二要素認証となっていない

  2. 1

    SMSを攻撃者に受信されたり、一時コードを偽サイトへ入力したりする危険がある

  3. 2

    携帯電話が流出するとパスワードなしで不正ログインされる可能性がある

  4. 3

    パスワードの入力もスマホで行うので、どちらも所持要素であり、二要素認証となっていない

正答と解説を確認

正答1. SMSを攻撃者に受信されたり、一時コードを偽サイトへ入力したりする危険がある

解説

パスワードは知識要素、登録した電話番号へ届くSMSの一時コードは所持要素に基づくため、二要素認証に当たる。ただし、攻撃者にSMSを受信されたり、偽サイトへ一時コードを入力したりしてコードを奪われる危険がある。

QUESTION 151#center_style_original_202608_0080

WebブラウザでHTTPSのURLへアクセスするときに使われるDNSとHTTPSの役割を説明したものとして最も適当なものを次から選べ。

  1. 0

    DNSがWebページの内容を暗号化し、HTTPSがドメイン名をIPアドレスへ変換する

  2. 1

    DNSもHTTPSも画像を圧縮する方式であり、接続先の確認や通信の保護には使わない

  3. 2

    DNSがホスト名からIPアドレスを調べ、HTTPSがブラウザとWebサーバ間の通信を暗号化する

  4. 3

    HTTPSで接続できれば、掲載内容や主張も全て事実であると保証される

正答と解説を確認

正答2. DNSがホスト名からIPアドレスを調べ、HTTPSがブラウザとWebサーバ間の通信を暗号化する

解説

DNSは、URLに含まれるホスト名から接続先のIPアドレスを調べる名前解決を行う。HTTPSは、ブラウザとWebサーバの間の通信を暗号化し、通信途中での盗聴や改ざんを防ぎやすくする。通信が保護されていても、掲載情報の正しさは別に確認する必要がある。

QUESTION 152#center_style_original_202608_0082

Webサービスで、ブラウザが商品IDを送信し、別のコンピュータが在庫データベースを検索して結果を返す。この役割分担の説明を次から選べ。

  1. 0

    画面を表示するブラウザがサーバで、在庫を検索して返す側がクライアントである

  2. 1

    ブラウザがクライアントで、検索処理と結果を提供する側がサーバである

  3. 2

    商品IDを送るブラウザも結果を返す側も、要求を出すかどうかにかかわらず両方サーバである

  4. 3

    処理性能が高い側をサーバと呼び、要求を送る側・返す側という役割は考慮しない

正答と解説を確認

正答1. ブラウザがクライアントで、検索処理と結果を提供する側がサーバである

解説

サービスを要求する側をクライアント、要求を受けて処理結果を提供する側をサーバという。機器の大きさや性能ではなく、その通信での役割による分類なので、同じコンピュータが状況により両方の役割を担うこともある。

QUESTION 153#center_style_original_202608_0083

プログラムがWeb上のページを自動巡回して収集し、検索用の索引を作る検索エンジンの方式を次から選べ。

  1. 0

    ディレクトリ型

  2. 1

    サイト内検索型

  3. 2

    メタ検索型

  4. 3

    ロボット型

正答と解説を確認

正答3. ロボット型

解説

クローラやロボットと呼ばれるプログラムがページを巡回・収集し、索引を作る方式をロボット型と呼ぶ。ディレクトリ型は人手などでWebサイトを分類登録する方式、サイト内検索型は特定サイト内を検索する方式、メタ検索型は複数の検索エンジンに問い合わせて結果を統合する方式である。

QUESTION 154#center_style_original_202608_0095

無線イヤホンをスマートフォンへ直接接続し、数m程度の近距離で比較的低消費電力のデジタル音声通信を行う規格を次から選べ。

  1. 0

    NFC

  2. 1

    Bluetooth

  3. 2

    Wi-Fi

  4. 3

    5G携帯電話通信

正答と解説を確認

正答1. Bluetooth

解説

Bluetoothは近距離の機器間を低消費電力で無線接続でき、対応プロファイルや方式で音声を伝送する。NFCは数cm程度の非常に近い距離で識別や少量データ交換に使われ、イヤホンへの連続音声伝送の方式とはいえない。

QUESTION 155#center_style_original_202608_0097

大学内の複数棟を大学が管理する回線で結び、その学内ネットワークを通信事業者の広域回線で海外拠点へ接続した。前者と後者の分類を次から選べ。

  1. 0

    前者はWAN、後者はLAN

  2. 1

    前者はLAN、後者はWAN

  3. 2

    前者も後者もPAN

  4. 3

    前者も後者も無線LANだけを意味する

正答と解説を確認

正答1. 前者はLAN、後者はWAN

解説

LANとWANは、主に地理的な範囲と管理のされ方で区別する。建物や構内など限定範囲を一組織が管理する網はLAN、離れた拠点を通信事業者の回線などで結ぶ網はWANと考える。有線か無線かは別の分類軸である。

QUESTION 156#center_style_original_202608_0104

異なるメーカーの機器同士が同じネットワークで通信するため、通信プロトコルが共通に定める内容を次から選べ。

  1. 0

    メッセージの形式だけを定め、送受信の順序や異常時の処理は実装ごとに互換性なく決める

  2. 1

    物理コネクタの形だけを定め、送信するビット列の意味や手順は定めない

  3. 2

    メッセージの形式、送受信の手順、タイミング、誤り時の扱い

  4. 3

    暗号方式だけを共通化し、暗号化前後のメッセージ形式と応答手順は定めない

正答と解説を確認

正答2. メッセージの形式、送受信の手順、タイミング、誤り時の扱い

解説

構文・意味・順序・タイミング・異常処理を共通化することで異なる実装間の通信を成立させる。形式だけでなく、どの順序で何を返すか、異常時にどう処理するかも共通化する必要になる。

QUESTION 157#center_style_original_202608_0105

大きなデータを複数のパケットに分割してパケット交換網で送る利点を次から選べ。

  1. 0

    各パケットが同じ経路を同じ遅延で通るよう、送信側だけで経路を固定する

  2. 1

    分割後のパケットは到着順に並ぶので、宛先や並べ直しの情報を付けなくてよい

  3. 2

    複数通信で回線を共有しやすく、損失時に必要な部分だけを再送しやすい

  4. 3

    パケットを細かくするほどヘッダの割合が下がり、最終的に付加情報がゼロになる

正答と解説を確認

正答2. 複数通信で回線を共有しやすく、損失時に必要な部分だけを再送しやすい

解説

短い単位で通信を多重化でき、データ全体ではなく失われた単位を再送する設計が可能になる。パケットは転送時の状況により別の経路や遅延になる場合があり、分割自体は同一路を保証しない。

QUESTION 158#center_style_original_202608_0106

TCPを用いた通信でデータを含む一部のセグメントが失われたとき、信頼性を確保するための処理を次から選べ。

  1. 0

    受信側が欠けた内容を前後のデータから推測し、確認応答を返さず完了とする

  2. 1

    シーケンス番号、確認応答、再送タイマなどで損失を検出し、未確認のデータを再送する

  3. 2

    失われたセグメントを飛ばし、後続データの順序番号を詰め直してアプリへ渡す

  4. 3

    IP層が全セグメントの到着確認と再送を行うため、TCPは損失を管理しない

正答と解説を確認

正答1. シーケンス番号、確認応答、再送タイマなどで損失を検出し、未確認のデータを再送する

解説

TCPはデータに順序を示す番号を付け、確認応答が届かない範囲を再送して、欠落と順序の乱れを補う。IPはパケットを宛先へ運ぶが、到着確認や再送による信頼性は主にTCPが担当する。

QUESTION 159#center_style_original_202608_0108

端末Aから別ネットワークのサーバBへ通常の宛先ベースのIP転送を行う。途中のルーターが次の転送先を決める際に主として使う情報を次から選べ。

  1. 0

    送信元IPアドレス

  2. 1

    リンク層の送信元MACアドレスとDNSのキャッシュ

  3. 2

    TCPの送信元ポート番号

  4. 3

    パケットの宛先IPアドレスとルーターの転送表

正答と解説を確認

正答3. パケットの宛先IPアドレスとルーターの転送表

解説

宛先IPアドレスを転送表の宛先プレフィックスと照合し、最も適した次ホップと出力インタフェースを決めるといえる。通常の宛先ベース転送では送信元だけで経路を選ばず、最終到達先を示す宛先を照合する。

QUESTION 160#center_style_original_202608_0110

IPパケットを構成するIPヘッダとデータ部の役割の組合せを次から選べ。

  1. 0

    ヘッダは受信後の表示だけに使い、途中のルータはデータ部だけを見て転送する

  2. 1

    ヘッダには送信元・宛先などの制御情報が入り、データ部には上位層から渡された内容が入る

  3. 2

    ヘッダには画像などの内容を入れ、データ部には宛先IPアドレスだけを入れる

  4. 3

    通信誤りに備え、ヘッダとデータ部には同じ制御情報と内容を二重に記録する

正答と解説を確認

正答1. ヘッダには送信元・宛先などの制御情報が入り、データ部には上位層から渡された内容が入る

解説

IPヘッダには、送信元・宛先のIPアドレスなど、パケットを配送するための制御情報が入る。データ部には、TCPなど上位の仕組みから渡された内容が入る。ルータはヘッダの宛先IPアドレスを参照して転送する。

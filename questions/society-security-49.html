QUESTION 481#center_style_original_202608_0410

オンラインサービスAから認証情報の漏えいが発表された。利用者はAと同じパスワードをサービスB・Cでも使っていた。使い回しによる被害を抑えるため、最初に行う対応として最も適当なものを次から選べ。

  1. 0

    A・B・Cをそれぞれ異なる長い値へ変更し、利用履歴を確認して多要素認証も有効にする

  2. 1

    漏えい元のAだけを新しい値へ変更し、同じ値を使っているB・Cは通知が来るまで維持する

  3. 2

    元の文字列の順序だけを変え、その新しい同一の文字列をA・B・Cへまとめて設定する

  4. 3

    A・B・Cの利用履歴だけを確認し、不審な記録が見つからなければ現在の値を使い続ける

正答と解説を確認

正答0. A・B・Cをそれぞれ異なる長い値へ変更し、利用履歴を確認して多要素認証も有効にする

解説

漏えいした認証情報を別のサービスで試す攻撃を、リスト型攻撃という。Aと同じパスワードをB・Cでも使っていたなら、三つすべてを異なる長いパスワードへ変更する。さらに利用履歴やログイン中の端末を確認し、多要素認証を有効にすると、既に生じた不正利用の発見と再発防止に役立つ。

QUESTION 482#center_style_original_202608_0426

データベースで、不正な更新を監査ログと保存済みハッシュで検出し、サーバ障害時には同期済み予備サーバへ切り替えた。主に高めた性質の組合せを次から選べ。

  1. 0

    不正更新の検出―可用性、予備サーバへの切替え―完全性

  2. 1

    不正更新の検出―機密性、予備サーバへの切替え―真正性

  3. 2

    不正更新の検出―可用性、予備サーバへの切替え―機密性

  4. 3

    不正更新の検出―完全性、予備サーバへの切替え―可用性

正答と解説を確認

正答3. 不正更新の検出―完全性、予備サーバへの切替え―可用性

解説

保存済みハッシュや監査ログによる変更検出は完全性、予備サーバへの切替えは可用性を支える。暗号化による閲覧制限は主に機密性を支える。

QUESTION 483#center_style_original_202608_0427

組織が境界ファイアウォールを導入した後も行うべき多層的な情報セキュリティ対策を次から選べ。

  1. 0

    ファイアウォールがあれば、内部端末の更新とパスワード管理を全て廃止する

  2. 1

    許可通信は全て安全とみなし、宛先確認と不審ファイル対策を行わない

  3. 2

    規則を設定せず全通信を許可し、攻撃を発見しないようログも残さない

  4. 3

    OS・アプリの更新、強固な認証、端末防御、ログ監視、利用者教育も組み合わせる

正答と解説を確認

正答3. OS・アプリの更新、強固な認証、端末防御、ログ監視、利用者教育も組み合わせる

解説

ファイアウォールで防げない許可通信内の攻撃、内部不正、端末脆弱性、認証情報窃取などへ多層的な対策で備える。外部からの通信制御だけでは、端末の脆弱性悪用や盗まれた認証情報、内部からの攻撃を防ぎ切れないといえる。

QUESTION 484#center_style_original_202608_0430

学校のWebサイトに、外部のWebサイトで見つけたイラストを掲載したい。著作権を踏まえた対応として最も適当なものを次から選べ。

  1. 0

    公開ページの画像は自由に使えると考え、掲載元の名称だけを添えて転載する

  2. 1

    学校の非営利活動なら許諾は不要と考え、利用条件を確認せずに掲載する

  3. 2

    色や大きさを変更すれば別の著作物になると考え、元画像の権利を確認せず掲載する

  4. 3

    利用規約やライセンスを確認し、必要なら権利者の許諾を得て、認められた条件で掲載する

正答と解説を確認

正答3. 利用規約やライセンスを確認し、必要なら権利者の許諾を得て、認められた条件で掲載する

解説

インターネット上で閲覧できることと、自由に転載できることは別である。画像にも原則として著作権が生じるため、利用規約、ライセンス、権利者の許諾を確認する。出典表示が必要な場合は、その方法も条件に従う。

QUESTION 485#center_style_original_202608_0431

広告メールの配信について、受信者から事前のオプトイン同意を得る画面設計を次から選べ。

  1. 0

    別の申請手続で得たメールアドレスを、広告の目的・内容・送信者を説明せず配信先へ自動登録する

  2. 1

    配信目的・内容・送信者を明示し、初期状態で未選択の同意欄を本人が自発的に選べるようにする

  3. 2

    広告配信への同意欄を初期状態で選択済みにし、解除方法や配信内容の説明を画面外へ配置する

  4. 3

    一度選択した広告配信への同意は撤回できないものとし、メールにも画面にも配信停止方法を設けない

正答と解説を確認

正答1. 配信目的・内容・送信者を明示し、初期状態で未選択の同意欄を本人が自発的に選べるようにする

解説

何に同意するかを理解できる情報を示し、本人の能動的な操作で明確な事前同意を記録する設計が適切である。別目的で取得したアドレスを説明なく広告へ使うと、広告受信への同意を得たことにならないといえる。

QUESTION 486#center_style_original_202608_0436

ランサムウェア感染端末を隔離し、影響範囲の調査を終えた。最新バックアップは端末に常時接続されていたため暗号化され、1日前の切離し保管バックアップは検査で正常だった。復旧方法として最も適当なものを次から選べ。

  1. 0

    暗号化された最新バックアップで正常な1日前の世代を上書きしてから復元する

  2. 1

    感染した環境をネットワークへ再接続し、原因を除去せず復元データを上書きする

  3. 2

    安全に初期化・再構築した環境へ、正常と確認した1日前のバックアップを復元する

  4. 3

    証拠とログを削除し、未検査の実行ファイルを他端末へ配って動作確認する

正答と解説を確認

正答2. 安全に初期化・再構築した環境へ、正常と確認した1日前のバックアップを復元する

解説

侵害要因を除いたクリーンな環境を用意し、マルウェアがないと検証した復元可能な世代を使うことで再感染を避けやすいといえる。破損した世代で健全な世代を上書きすると、利用可能な復旧点を失う。世代は保全して検証する。

QUESTION 487#center_style_original_202608_0437

送信者Aが受信者B向けに文書を暗号化し、Aのデジタル署名も付けた。Bが文書を復号し、Aの署名を検証するときに使う鍵の組合せを次から選べ。

  1. 0

    復号にはBの公開鍵、署名検証にはAの秘密鍵

  2. 1

    復号にはAの秘密鍵、署名検証にはBの公開鍵

  3. 2

    AとBの秘密鍵を文書へ添付し、両方を公開して使う

  4. 3

    復号にはBの秘密鍵、署名検証には信頼できるAの公開鍵

正答と解説を確認

正答3. 復号にはBの秘密鍵、署名検証には信頼できるAの公開鍵

解説

Bの公開鍵で保護された情報はBの秘密鍵で復号し、Aの秘密鍵で作った署名はA本人に対応する公開鍵で検証する。Bの公開鍵は暗号化側で使い、復号には秘密鍵が必要である。署名検証でAの秘密鍵を受信者へ渡してはならない。

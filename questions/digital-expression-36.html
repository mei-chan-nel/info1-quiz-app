QUESTION 351#center_style_original_202608_0366

4ビットの2の補数表現0101を、値を変えずに8ビットへ符号拡張したビット列を次から選べ。

  1. 0

    00010101

  2. 1

    01010000

  3. 2

    11110101

  4. 3

    00000101

正答と解説を確認

正答3. 00000101

解説

2の補数の符号拡張では、元の最上位ビットを左へ繰り返す。正数は0、負数は1で埋めると値を保てる。

QUESTION 352#center_style_original_202608_0367

10進数−37を8ビットの2の補数表現にしたビット列を次から選べ。

  1. 0

    11011011

  2. 1

    00100101

  3. 2

    10100101

  4. 3

    11011010

正答と解説を確認

正答0. 11011011

解説

nビットの2の補数で−aを作る手順は、aをnビットで表し、全ビットを反転して1を加えることである。得たビット列を同じ操作にかけると絶対値を確認できる。

QUESTION 353#center_style_original_202608_0368

連続的に変化するアナログ音声を、標本化・量子化・符号化によってビット列として扱えるように変換することを次から選べ。

  1. 0

    時間軸上で一定間隔の値を取り出す標本化だけ

  2. 1

    標本化・量子化・符号化を通じてビット列へ変えるデジタル化

  3. 2

    取り出した振幅を有限個の段階へ丸める量子化だけ

  4. 3

    段階値を0と1の列へ対応させる符号化だけ

正答と解説を確認

正答1. 標本化・量子化・符号化を通じてビット列へ変えるデジタル化

解説

音声のデジタル化は、時間方向に値を取り出す標本化、振幅を有限段階へ丸める量子化、その段階をビット列にする符号化の順で進む。三つの用語は、それぞれ処理全体ではなく異なる段階を表す。

QUESTION 354#center_style_original_202608_0369

音声の振幅を−1.0から1.0の範囲で表した値が−0.42であった。量子化で選べる段階値が−1.0、−0.5、0.0、0.5、1.0で、最も近い値へ対応させるときの量子化値を次から選べ。

  1. 0

    −1.0

  2. 1

    −0.5

  3. 2

    0

  4. 3

    0.5

正答と解説を確認

正答1. −0.5

解説

最も近い段階へ量子化するときは、元の値との差の絶対値が最小になる段階を選ぶ。−0.42と−0.5の差は0.08で、他の候補との差より小さい。元の値と量子化後の値との差を量子化誤差という。

QUESTION 355#center_style_original_202608_0370

27 kHzの正弦波を標本化周波数20 kHzで標本化した。周波数の折り返し関係だけを考えるとき、0～10 kHzの範囲に現れる成分の周波数を次から選べ。

  1. 0

    3 kHz

  2. 1

    13 kHz

  3. 2

    20 kHz

  4. 3

    7 kHz

正答と解説を確認

正答3. 7 kHz

解説

標本化周波数をfₛとすると、fₛ/2を超える成分は0～fₛ/2の範囲へ折り返して見えることがある。候補となる|f－k fₛ|のうち、この範囲に入る値を選ぶ。ここでは|27－20|＝7 kHzである。

QUESTION 356#center_style_original_202608_0371

横1,920画素、縦1,080画素、1画素24ビットの非圧縮画像を、100 MBの空き領域へ保存する。付加情報とパディングを無視し、1 MB=1,000,000バイトとすると、完全に保存できる最大枚数を次から選べ。

  1. 0

    15枚

  2. 1

    17枚

  3. 2

    18枚

  4. 3

    16枚

正答と解説を確認

正答3. 16枚

解説

保存可能な個数は、容量を1枚分で割った商の整数部分で求める。1枚は1,920×1,080×24÷8＝6,220,800バイト、100,000,000÷6,220,800≈16.08なので16枚である。端数の1枚は完全には保存できない。

QUESTION 357#center_style_original_202608_0372

UTF-8で符号化された文書のバイト列を、受信側が誤ってShift_JISとして解釈したため文字化けした。元のバイト列が残っているときの対処を次から選べ。

  1. 0

    文字化けした表示結果をShift_JISで上書き保存し、元のバイト列も置き換える

  2. 1

    UTF-8のバイト列を一度画像に変換し、OCRで元文字を推測する

  3. 2

    元のバイト列を保持したまま、受信側の文字コード指定をUTF-8へ直して読み込む

  4. 3

    文字コードを指定せず、異なる候補で上書き保存を繰り返す

正答と解説を確認

正答2. 元のバイト列を保持したまま、受信側の文字コード指定をUTF-8へ直して読み込む

解説

文字化けは、同じバイト列を異なる文字コードで解釈しただけなら、元バイトを保って正しい方式で読み直せる。誤表示の文字列で上書きすると元バイトを失い、復元が難しくなる。

QUESTION 358#center_style_original_202608_0379

カラー印刷で、シアン・マゼンタ・イエローのインクが特定の波長の光を吸収し、重ねるほど反射光が少なくなる色の混合方式を次から選べ。

  1. 0

    赤・緑・青の光を加えるほど明るくなる加法混色

  2. 1

    インクが光を吸収し、重ねるほど反射光が減る減法混色

  3. 2

    色を混ぜず、異なる色の細かな点を並べて平均的に見せる併置混色

  4. 3

    インクの補色を等量混ぜると、白色光を放射する加法混色になる

正答と解説を確認

正答1. インクが光を吸収し、重ねるほど反射光が減る減法混色

解説

CMYの色材が波長を引き算するように吸収し、重ねるほど暗くなる。発光するディスプレイのRGBに使う方式で、インクによる吸収とは逆である。

QUESTION 359#center_style_original_202608_0380

テレビやディスプレイで、赤・緑・青の光を強くするほど明るくなり、三色を十分な強さで重ねると白に近づく色の混合方式を次から選べ。

  1. 0

    減法混色

  2. 1

    加法混色

  3. 2

    顔料混色

  4. 3

    網点印刷

正答と解説を確認

正答1. 加法混色

解説

加法混色は光を足す方式で、重ねるほど明るくなる。印刷の減法混色はインクが光を吸収する方式で、重ねるほど暗くなるため、使う場面と明るさの変化で区別する。

QUESTION 360#center_style_original_202608_0381

4ビットを全て値の大きさに使う符号なし整数表現で、表現できる10進整数の範囲を次から選べ。

  1. 0

    0～15

  2. 1

    0～16

  3. 2

    −8～7

  4. 3

    −15～15

正答と解説を確認

正答0. 0～15

解説

nビットの符号なし整数は全ビットを値に使うため、最小0、最大2ⁿ−1である。4ビットなら0000₂～1111₂、すなわち0～15となる。2ⁿは値の個数であり最大値ではない。

QUESTION 251#center_style_original_202608_0052

8ビットの16進数FBと0Fの各ビットについてAND演算を行った結果を、2桁の16進数で表したものを次から選べ。

  1. 0

    FB

  2. 1

    0B

  3. 2

    F0

  4. 3

    0F

正答と解説を確認

正答1. 0B

解説

16進数同士のビット演算は、各桁を4ビットへ直して考えられる。Fは1111なので、ANDでは相手側の4ビットをそのまま残すマスクになる。

QUESTION 252#center_style_original_202608_0053

横10画素、縦20画素の白黒画像を、1画素当たり1ビットで表す。画像データは画素の情報だけからなり、1バイト＝8ビットとするとき、この画像のデータ量を次から選べ。

  1. 0

    20バイト

  2. 1

    40バイト

  3. 2

    200バイト

  4. 3

    25バイト

正答と解説を確認

正答3. 25バイト

解説

画像のデータ量は、横の画素数×縦の画素数×1画素当たりのビット数で求める。10×20×1＝200ビットであり、8で割ると25バイトになる。ヘッダや圧縮などを考えない問題では、与えられた画素の情報量から換算する。

QUESTION 253#center_style_original_202608_0054

各レコードに64ビットの識別子を1個ずつ格納する。1000件分について、識別子だけが占めるデータ量をバイトで表した値を次から選べ。

  1. 0

    8000バイト

  2. 1

    64000バイト

  3. 2

    1000バイト

  4. 3

    8000000バイト

正答と解説を確認

正答0. 8000バイト

解説

同じ大きさの固定長データを複数保存するなら、1件分をバイトへ直して件数を掛ける。64ビット＝8バイトなので1,000件で8,000バイトとなる。

QUESTION 254#center_style_original_202608_0055

容量2 KiBの領域に、1個600バイトのファイルを分割せずに格納する。1 KiB＝1024バイトとするとき、格納できる最大個数と残り容量の組合せを次から選べ。

  1. 0

    3個、248バイト

  2. 1

    4個、352バイト

  3. 2

    3個、48バイト

  4. 3

    2個、848バイト

正答と解説を確認

正答0. 3個、248バイト

解説

ファイルを分割できないとき、格納個数は容量÷ファイルサイズの整数部分である。残り容量が1個分未満なら、空きがあっても追加できない。

QUESTION 255#center_style_original_202608_0056

1画素をR・G・Bそれぞれ8ビットで表し、透明度情報は持たない。1画素で表現できる色数を次から選べ。

  1. 0

    256色

  2. 1

    24色

  3. 2

    16777216色

  4. 3

    768色

正答と解説を確認

正答2. 16777216色

解説

独立な成分の組合せ数は掛け算で数える。RGB各8ビットなら各256段階なので256³色となり、単に256を3倍するのではない。

QUESTION 256#center_style_original_202608_0057

入力が0または1のいずれかである論理否定（NOT）回路の働きを次から選べ。

  1. 0

    入力が1なら出力0、入力が0なら出力1になる

  2. 1

    入力が1なら出力1、入力が0なら出力0になる

  3. 2

    入力値にかかわらず出力を0に固定する

  4. 3

    入力値にかかわらず出力を1に固定する

正答と解説を確認

正答0. 入力が1なら出力0、入力が0なら出力1になる

解説

NOTは入力を一つだけ取り、0と1を反転する論理演算である。入力と出力の組は0→1、1→0となる。ANDやORは二つ以上の入力の組合せを扱う点が異なる。

QUESTION 257#center_style_original_202608_0067

動画配信で、再生に必要な速度より受信速度が一時的に遅くなっても再生停止を減らす仕組みを次から選べ。

  1. 0

    受信済みデータをバッファに一定量蓄えてから順に再生する

  2. 1

    再生画面だけを小さくし、受信する動画のデータ量は変えない

  3. 2

    受信速度が低下したときに再生速度をさらに上げる

  4. 3

    再生を始めたら通信を止め、再生終了後に残りを受信する

正答と解説を確認

正答0. 受信済みデータをバッファに一定量蓄えてから順に再生する

解説

バッファは受信済みデータを一時的に蓄える領域で、短時間の速度低下を吸収する。低速状態が長く続けば蓄えを使い切るため、再生停止を完全には防げない。配信側が低い画質・ビットレートへ切り替える方式と併用されることもある。

QUESTION 258#center_style_original_202608_0075

解像度300 dpiで、横2インチ、縦3インチの長方形を読み取る。生成される画像の総画素数を次から選べ。

  1. 0

    540000画素

  2. 1

    90000画素

  3. 2

    1800画素

  4. 3

    1620000画素

正答と解説を確認

正答0. 540000画素

解説

dpiは1インチ当たりの画素数である。横画素数＝dpi×横のインチ数、縦も同様に求め、最後に掛けて総画素数を得る。

QUESTION 259#center_style_original_202608_0076

2進数1101から2進数0011を引いた結果を、4ビットの2進数で表したものを次から選べ。

  1. 0

    1000

  2. 1

    1110

  3. 2

    1100

  4. 3

    1010

正答と解説を確認

正答3. 1010

解説

桁数をそろえて引く方法のほか、いったん10進数へ直して確認できる。1101₂＝13、0011₂＝3なので差は10、4ビットの2進数では1010₂である。変換して確かめる方法は、筆算の検算にも使える。

QUESTION 260#center_style_original_202608_0077

同じ動画を、ネット配信用と繰り返し編集する保存用にそれぞれ用意する。用途に応じた圧縮方式を選ぶ観点を次から選べ。

  1. 0

    動画形式を選ぶとき、利用する再生・編集環境との互換性は考慮しない

  2. 1

    非可逆圧縮で捨てた情報は、展開時に元のビット列へ完全復元できると考える

  3. 2

    拡張子が同じファイルなら、内部の圧縮方式・ビットレート・画質も同じだと判断する

  4. 3

    配信用では通信量と画質の均衡、編集保存用では再圧縮による劣化と編集しやすさを考える

正答と解説を確認

正答3. 配信用では通信量と画質の均衡、編集保存用では再圧縮による劣化と編集しやすさを考える

解説

動画形式は用途に応じて選ぶ。配信では通信量・画質・再生開始までの時間、編集保存では再圧縮による劣化や編集のしやすさが重要になる。利用する端末やソフトウェアが方式に対応しているかも確認する必要がある。

# 問題検索の改修・検証記録

2026年11月9日。問題データ1,438問・公開タグ225種類を対象に検証。

## 実装

従来は全問の問題文・選択肢・解説を非表示HTMLとして生成していた。初期DOMは57,552要素あり、タグ操作ごとに全問を並べ替え、全タグの件数を個別に再計算していた。さらに、タグ説明用のMutationObserverがルート全体の属性変更を監視していた。

改修後は生成元の問題データを変更せず、全文検索用の `questions/filter-data.json` を生成する。最初の有効な検索時に一度取得し、全問の問題文・選択肢・全体解説・各選択肢の解説を検索する。本文と解説のDOM生成は検索とは独立し、検索結果を10問ずつ追加する。追加時には既存カードを作り直さず、解答・解説の開閉状態を保持する。解説DOMは手動で開いたときに生成する。

タグの件数は現在のタグ条件に一致する問題群から一度に集計し、キーワード変更や追加描画では再計算しない。不要になったタグ説明、用語ページリンク、DOM監視、検索ページでの用語ガイドの自動取得を削除した（学習アプリが利用する取得APIは保持）。出題コンテキストの保存形式・ランダム抽出・アプリのURLパラメータは従来どおり。

キーワードの空白区切りはAND条件。選択した検索対象全体で各語の一致を判定する。大文字小文字・全角半角は正規化する。変換中は検索を行わず、入力確定後250msで検索する。キーワードとタグは互いの条件を解除し、戻る・進むで条件を復元する。旧タグURL、別表記、問題IDによるフォーカス指定は引き続き扱う。

検索ページでの正誤確認はDOM内だけに保持し、学習記録や回答集計へ書き込まない。正答は学習アプリと同じ薄緑、選択中の誤答は薄赤。解説は自動で開かない。

## 検証

- 統合検証 `validate_study_atlas.py`：合格。
- JavaScript 87件、Python 10件：合格。
- 全問題・全選択肢のID、本文、正答、全解説が元データと一致し、新着順を維持することを検証。
- 全体・各選択肢の全解説を実際の検索関数へ入力し、対象問題が漏れなく検索できることを検証。
- 全公開タグ、複数タグAND、空欄、検索対象なし、複数語と全角空白を検証。
- ChromiumでPC幅1440×1000、モバイル幅390×844・タッチ操作を確認。
- IME変換途中の抑制、選択肢の選び直し、解説の手動展開、追加読み込み、履歴の戻る、旧URL、検索間の条件解除、学習用ストレージへの非記録を確認。
- 検索結果全件を候補としてアプリへ受け渡すことを確認。アプリ起動時のSupabase読み取りAPIはテスト応答を使い、外部への書き込みは行っていない。
- データ取得中に条件を解除した場合、古い結果が再表示されないことを確認。
- PC・モバイルのスクリーンショットでレイアウトと正誤表示を目視確認。

## 性能比較

同じローカルサーバー、Chromium、CPU 4倍スロットリング、各3回の中央値。外部の広告・計測リクエストは遮断した。実機・本番ネットワークでの値ではない。

| 指標 | PC 改修前 → 後 | モバイル幅 改修前 → 後 |
| --- | --- | --- |
| 初期HTML（非圧縮） | 3,442,038 → 約52,900 bytes | 同左 |
| 初期DOM要素数 | 57,552 → 826 | 同左 |
| DOMContentLoaded | 2,478.5 → 513.6 ms | 2,233.1 → 497.3 ms |
| LCP | 672 → 480 ms | 480 → 440 ms |
| CLS | 0.0157 → 0 | 0.0231 → 0 |
| タグ操作の最大イベント時間 | 800 → 72 ms | 816 → 64 ms |

イベント時間はEvent Timing APIで測った操作応答の参考値であり、実ユーザーのINPではない。本番LCP・CLS・INPは公開後の実測で継続確認する必要がある。公開サイトへの接続は実行環境のネットワーク制限で遮断されたため、本番サイト自体の検証は行っていない。

全件検索にはページのキーワード検索を使う。ブラウザのページ内検索やText Fragmentで検索できる範囲は描画済みの問題となる。JavaScript無効時に全問の静的HTMLを表示する方式は、初期HTMLからのデータ分離に伴い廃止した。
